# 0007: テストコードは、ファイルの中身を grep・正規表現で読んで確かめない

[0006](./0006-config-tests-evaluate-with-the-tool.md) を設定・IaC から**すべてのテストコード**に広げる。

## 決めたこと

- **テストコードの中で、ファイルの中身を grep・awk・正規表現で読んで確かめない。** 読む相手が実装のソースでも、設定・IaC でも、文書でも同じ。
- 代わりに、対象を**実行して**出力・戻り値・副作用を観測する。設定・IaC・文書なら、**そのツール自身**（スキルが見出しを読むときの読み取り器、IaC ツールの評価やプラン出力など）に評価させた値を見る。
- なぜか: 確かめているのが「ソースにこう書いてあるか」であって「実際にどう振る舞うか」ではない。書き方が変わるだけで空振りするか落ちる。切り出しをテストごとに別実装で持つと、条件も本物と食い違っていく。

## 対象にしないもの

- **テストコード以外。** hook・CI のステップ・スクリプトが grep や正規表現を使うのは対象外。テキストを走査すること自体が目的のもの（公開してはいけない語の検出など）は、テストではなく CI のステップに置く。
- **実行して得た出力**を正規表現で照合すること。読んでいるのはファイルではなく振る舞いの結果なので構わない。

## 評価できない形なら、テストより先にコードを分ける

外部の参照があって評価できない、埋め込みのスクリプトがあって実行できない、といったときは、テストを曲げずにコードを分ける。純粋な部分を関数・別ファイルに切り出し、外の参照は引数で渡す。

## 既存のテストは、触るときに移す

一度に直さない。**新しく書くテストからは禁止する。** 既存のテストは、そのテストか対象のコードに手を入れるときに移す。

## 効かせ方

上流の `tdd` は書き換えられないので、効かせるのはレビュー側になる。`review-dialogue` が上流 `code-review` に [`standards.md`](../../plugins/dev-workflow/skills/review-dialogue/standards.md) を Standards の基準として渡し、違反を指摘に挙げる。
