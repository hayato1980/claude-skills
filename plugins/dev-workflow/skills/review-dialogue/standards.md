# レビューの基準（Standards の軸に足す文書）

`review-dialogue` が上流 `code-review` を呼ぶとき、Standards の軸の「基準を書いた文書」としてこのファイルを渡す。ここに書いたものは、リポが文書化した基準と同じ扱いで、**文書化された基準の違反として指摘してよい**（baseline の smell のような判断の問題ではない）。

## 設定・IaC のテストは、ソースを正規表現で読まない

差分に設定・IaC のテストの**追加または変更**があり、そのテストが対象の**ソースを正規表現・awk・grep で切り出して**中身を確かめているなら、Standards の指摘として挙げる。

- 基準の正本: [判断 0006](https://github.com/hayato1980/claude-skills/blob/main/docs/decisions/0006-config-tests-evaluate-with-the-tool.md)
- 直し方: そのツール自身に評価させた値を読む。評価できない形なら、先にコードを分ける。
- **既存のテストを触っていないなら指摘しない**（既存は触るときに移す。新しく書くテストからが対象）。
- 指摘の本文には、読んでいるソースの切り出し箇所と、代わりに評価させるべき値を書く。
