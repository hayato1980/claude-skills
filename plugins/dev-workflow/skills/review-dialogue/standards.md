# レビューの基準（Standards の軸に足す文書）

`review-dialogue` が上流 `code-review` を呼ぶとき、Standards の軸の「基準を書いた文書」としてこのファイルを渡す。ここに書いたものは、リポが文書化した基準と同じ扱いで、**文書化された基準の違反として指摘してよい**（baseline の smell のような判断の問題ではない）。理由・直し方・範囲の正本は [判断 0007](https://github.com/hayato1980/claude-skills/blob/main/docs/decisions/0007-tests-do-not-read-file-contents-with-regex.md)。ここには**何を指摘するか**だけを書く。

## テストコードがファイルの中身を grep・正規表現で読んでいる

- **指摘する:** 差分で**追加または変更**されたテストコードが、ファイルの中身（実装のソース・設定・IaC・文書）を grep・awk・正規表現で読んで確かめている。
- **指摘しない:**
  - 差分がそのテストにも対象のコードにも触れていない既存のテスト。
  - テストコード以外（hook・CI のステップ・スクリプト）が grep・正規表現を使っていること。
  - 対象を実行して得た出力を正規表現で照合していること。
- 本文には、読んでいるファイルと切り出し箇所を書き、判断 0007 を参照させる。
